# 方案修订说明（面向 WWW）

与 [../DESIGN_DECISIONS.md](../DESIGN_DECISIONS.md) 同步。实现相对 `研究方案.md` 的偏离及原因。标准是：WWW Graph-for-the-Web 审稿人会不会接受这条声称？

原始问题设定（三维 Web 异构图、结构性幻觉 H1–H5、冻结 MLLM 插件）保留。下列改动是为了**可运行、可审稿**，不是缩小贡献。

## 必须改的错误

1. **WebQA (CVPR 2022) 不能当网页结构主实验。** 它是维基百科图文多跳问答，没有 DOM/布局。正文主证据改为 WebHallu-Struct（模板留出）+ WebSRC 抽样 + VisualWebBench 可下载子集。
2. **Token 级稠密 TRB（n×n）在 4k 序列、32 头、FlashAttention 下不可部署。** 改为锚点图上的类型偏置（k≤48），用 STAR 把视觉 token 绑到区域。这比硬上 n×n 更接近 Graphormer 的原意。
3. **vLLM + 自定义层插件不兼容。** 评测用 HF `generate`，延迟表用实测，不写「vLLM 连续批处理」这种尚未实现的工程句。
4. **InternVL3 零样本插同一套插件**依赖隐藏维 3584 vs 4096 与不同视觉栈。跨家族作为 stretch，主对比是同底座 B0/B1/B3/M。

## 增强的创新点（相对原稿）

- **STAR**：用 `image_grid_thw` 还原每个视觉 token 的像素盒，与渲染 BBox 做 IoU 赋值。这是「结构定义锚点」落地的关键，用来切割 Perceiver/Q-Former。
- **锚点级 TRB + 零初始化残差门**：保证可训练、不破坏预训练。DOM 兄弟边按 `sibling_index`（源序），空间边按几何；二者不再混成同一种边。
- **StHR + 模板留出 vs 泄漏模板**：专门防合成数据循环论证。
- **hard_struct**：易混 SKU、密表、RTL 导航（视觉序≠文档序）、交叉图注。用来打破 8B OCR 天花板——标准 held-out 页面对 Qwen3-VL-8B 过易。
- **无 HTML 的空间网格回退**：让插件能在 WebSRC/VisualWebBench 截图上跑。

## 计算口径（本机）

单卡 A800 80GB。默认 SFT 3k×2 epoch。评测 held-out 用 500 题量级，而不是把诊断集题库全量生成一遍。

## 本机实验真正移动指针的是什么

易留出模板在短答 SFT 后饱和（LoRA = WebGAP = EM 100%）。插件仍有因果足迹：置换 STAR 列后 EM 掉到 26.6%（held-out）和 10.5%（hard_struct）。

在视觉≠DOM 页上、不做冲突 SFT 时，GraphToken（prompt 序列化）在源序探针上优于注意力插件（33% vs ~0%）。在不相交的 `hard_train` 上再跑 100 个优化步后，LoRA 与 WebGAP 都到约 99%，且 `dom`=100%。STAR 赋值被用到了；源序/视觉冲突主要是监督问题。完整条目见 [../DESIGN_DECISIONS.md](../DESIGN_DECISIONS.md)。
